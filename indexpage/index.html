01 · BACKGROUND

从"文字框"到"对话伙伴"的演进

大模型让机器第一次能"听懂人话"，但大多数对话产品仍停留在输入框 + 文字流的体验里—— 缺少形象、缺少声音、缺少"它就在那里"的临场感。

RealTimeTalk 把对话的载体升级为一位可亲的卡通形象 "普兰"： 她会呼吸、会眨眼、会思考、会说话、会讲解、会总结—— 让每一次问答都像是在与一位真实坐在你面前的知识伙伴交谈。

有表情的形象

实时语义切片动画，匹配讲解、强调、对比、举例等表达意图。

有温度的声音

Cherry 音色 TTS 合成，与动画口型、手势同步播放。

有依据的知识

内置 RAG 向量检索，引用专项知识库作答，有据可查。

有节奏的对话

流式分段生成 + 确认式播放，长回复也能丝滑衔接。

02 · PROBLEMS

现有对话产品的三个"不够好"

当用户面对一段长回复时，最常见的体验问题是什么？

1

注意力难以聚焦

大段回复仅以纯文字呈现，用户需要自行在脑中"重建画面"，认知负担重、阅读疲劳感强。

2

缺乏情感与温度

静态头像或无形象让对话显得"工具化"，用户难以建立信任与持续互动的意愿。

3

专业知识无据可依

通用模型容易"一本正经地胡说"，在企业知识问答、客服、教学等场景难以独立承担关键决策。

结论很直接 —— 仅靠"文字 + 静态形象"的方案，无法承载专业、可信、有温度的实时对话需求。

03 · SOLUTION

从"看文字"升级为"听 +看 +感受"

实时动画形象 + 同步语音 + 打字机气泡 + 专项知识库，相较于完全不动的形象 + 文字对话，能带来显著更优的用户体验—— 这是 RealTimeTalk 最朴素、也最关键的差异化。

传统方案

静态形象 / 无形象 + 纯文字

  • 形象固定不动，缺乏真实交流感
  • 用户必须自行阅读，无语音陪伴
  • 长回复一次性涌出，节奏拖沓
  • 知识无法溯源，幻觉难以察觉
  • 多轮对话上下文易丢失
  • 弱网下段间停顿明显
→
RealTimeTalk

实时动画形象 + 语音 + 知识

  • 待机呼吸 / 思考 / 讲解 / 强调 等 11+ 种语义动作实时切换
  • TTS 同步配音，逐字打字机气泡与声音严格对齐
  • 流式分段 + 确认式播放，长回复节奏自然
  • RAG 检索专项知识，回复可引用、可溯源
  • 智能摘要保留上下文，Token 溢出不丢记忆
  • 客户端 L1/L2 双层缓存，弱网段间停顿 < 200ms

05 · IMPLEMENTATION

从环境到上线的五步闭环

RealTimeTalk 设计为开箱即用 —— 一份 Docker Compose 即可拉起完整全栈。

1
准备环境

Docker 20+ / Compose v2
ECS 或任意 Linux 主机

2
准备切片

复制 .mkv 切片
convert_clips.py 转 WebM

3
填写配置

.env 填入 LLM 与
DashScope API Key

4
一键启动

docker compose up -d
访问 localhost 即可使用

5
知识接入

管理后台创建
pulan_* 集合并导入

本地一键启动

Qdrant + Redis + MinIO + Server + Nginx 五件套编排，弱网环境依旧能跑通。

生产 Docker Swarm

支持 ARM64 ECS 单节点发布，提供完整的 deploy-manual 操作手册。

知识库管理后台

独立 /admin 入口：集合管理、文档导入、检索测试，全可视化操作。

语音输入 (ASR)

按住说话即可转写填入输入框，按 ESC 取消，移动端同样可用。

所有切片、对话、视频产物均在 Docker 容器内编排，配置与代码完全解耦，便于二次定制。
