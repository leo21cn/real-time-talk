# Qdrant 向量知识库 — 客户端操作指南

## 一、概述

知识库采用 **RAG（检索增强生成）** 架构：当你向 AI 提问时，系统会自动将你的问题转为向量，在知识库中检索最相关的内容，注入到对话上下文中，让 AI 基于你的知识给出更精准的回答。

```
用户提问 → 向量化 → Qdrant 语义检索 → 注入上下文 → AI 回答
```

**关键概念：**

| 概念 | 说明 |
|------|------|
| **集合（Collection）** | 知识库的顶层容器，类似数据库中的"表"。可按主题分类创建多个集合（如 `test_kb`、`产品手册`） |
| **向量（Vector）** | 文本的数学表示（1024维），用于语义相似度计算 |
| **嵌入（Embedding）** | 将文本转换为向量的过程，由 DashScope `text-embedding-v3` 模型完成 |
| **分数（Score）** | 检索结果与查询的语义相似度，范围约 0~1，越高越相关 |

## 二、界面访问

**Web 操作地址：** `http://localhost/admin.html`（独立管理页面，与对话页面分离）

知识库管理面板为独立全屏页面，包含集合管理、知识摄入、知识搜索三个功能区。

### 2.1 Token 鉴权

首次访问管理页面时需要输入管理员 Token 进行身份验证：

1. 打开 `http://localhost/admin.html`，看到 Token 输入界面
2. 输入管理员 Token（默认值：`shleeyuan`，可在 `.env` 中通过 `KNOWLEDGE_ADMIN_TOKEN` 修改）
3. 点击「验证」，成功后进入管理界面
4. Token 验证通过后会保存在浏览器本地，下次访问无需重新输入
5. 点击右上角「退出登录」可清除 Token

## 三、集合管理

### 3.1 查看集合

展开面板后，顶部「**集合管理**」下拉框会列出所有已创建的集合及各自文档数量：

```
test_kb (15条)
产品手册 (32条)
常见问题 (8条)
```

选中某个集合后，后续的摄入和搜索操作默认针对该集合。

### 3.2 新建集合

1. 在「**新集合名称**」输入框中输入名称（支持中文、英文、数字）
2. 点击 **「+新建」** 按钮
3. 系统自动将名称规范化为小写+下划线格式（如 `我的知识` → `my_knowledge`）
4. 新集合创建后自动选中

### 3.3 删除集合

1. 确保下拉框中已选中要删除的集合
2. 点击红色 **「删除当前集合」** 按钮
3. 在弹出的确认框中点击「确定」
4. **⚠️ 警告**：集合中所有知识将被永久删除，不可恢复

## 四、知识摄入

### 4.1 添加知识内容

1. 确保已选中目标集合
2. 在「**添加知识**」文本框输入知识点内容
3. 点击蓝色 **「添加到当前集合」** 按钮
4. 成功后状态栏显示 `已添加 N 条知识`

### 4.2 自动分块机制

系统会自动处理长文本：

- **500 字符以内**：作为单条知识存储
- **超过 500 字符**：自动按段落（`\n\n`）切分，段落间有 100 字重叠以保证语义连续
- 超长段落按 500 字窗口滑动切分

### 4.3 摄入示例

**输入：**
```
普兰的办公室位于杭州西湖区文三路478号华星时代广场A座15层。
办公室窗外可以看到西湖全景，环境非常好。
公司成立于2020年，现有员工200人。
```

**结果：** 系统将这段文本作为 1 条知识向量化后存入 Qdrant。

**输入（长文本）：**
```
第一段关于产品的详细介绍...（300字）

第二段关于价格的说明...（300字）

第三段关于售后服务的政策...（300字）
```

**结果：** 系统自动按段落拆分为 3 条知识分别存储。

## 五、知识搜索（调试用）

### 5.1 语义搜索

1. 在「**搜索知识**」输入框输入关键词或问题
2. 按回车或点击黄色 **「搜索」** 按钮
3. 系统返回 Top 5 最相关的结果

### 5.2 搜索结果解读

每条结果显示：

```
[test_kb] score: 0.798
普兰的办公室位于杭州西湖区文三路478号...
```

| 字段 | 说明 |
|------|------|
| `[集合名]` | 该条知识所属的集合 |
| `score` | 语义相似度分数（0~1），越大越相关 |
| `文本内容` | 知识正文的前 200 字符 |

**注意：**
- 不选择集合时，系统会**跨所有集合**搜索
- 选择特定集合时，仅在该集合内搜索

## 六、工作原理详解

### 6.1 角色-集合映射

当前配置（`.env` 中的 `ROLE_COLLECTIONS`）：

```json
{"普兰": "*"}
```

- `"*"` 表示普兰角色会搜索**所有**集合
- 如需限定角色只搜特定集合，可修改为：`{"普兰": ["test_kb", "产品手册"]}`

### 6.2 对话中的 RAG 流程

当你在对话框中提问时，系统自动执行：

1. **向量化查询** — 将你的问题发送到 DashScope Embedding API，转为 1024 维向量
2. **多集合并发检索** — 根据角色配置，在指定（或所有）集合中并发搜索
3. **合并排序** — 合并各集合结果，按语义相似度降序排列，取 Top 5
4. **上下文注入** — 将检索结果构建为 system 消息，插入对话历史
5. **LLM 生成** — AI 基于知识库内容生成回答

### 6.3 纯 LLM 降级

以下情况会自动跳过 RAG，走纯通用 AI 回复：

- Qdrant 中没有任何集合
- 检索结果为空
- 最高分数低于 0.3（视为不相关）
- Qdrant 或 Embedding 服务不可用

## 七、最佳实践

### 7.1 知识编写建议

- **每条知识聚焦一个主题**：避免将无关信息混在一起
- **使用完整的陈述句**：向量模型对完整语义理解更好，例如写「普兰的办公室在杭州西湖区」而非「办公室：杭州」
- **控制在 300-500 字**：单条知识不宜过长，确保检索精度

### 7.2 集合组织建议

- **按主题分类**：产品信息、公司制度、技术支持、FAQ 等各自独立建集合
- **命名清晰**：使用有意义的名称，如 `product_manual`、`hr_policy`、`tech_faq`
- **定期清理**：删除过时或无效的知识，保持知识库质量

### 7.3 验证知识生效

1. 先在「搜索知识」框输入你的问题，确认能搜到期望的内容
2. 再在对话中提问，检查 AI 回答是否引用了知识库内容
3. 若回答未引用，检查：集合是否存在、知识是否已摄入、角色-集合映射是否正确

## 八、常见问题

**Q: 添加知识后对话中没有生效？**

A: 检查三点：① 确认下拉框选中了正确的集合；② 在搜索框中验证知识可被检索到；③ 确认 `.env` 中 `ROLE_COLLECTIONS` 包含该集合或设为 `"*"`。

**Q: 搜索结果分数很低（< 0.3）？**

A: 表示查询与知识语义不匹配，系统在对话中会自动跳过这些低分结果，走纯 AI 回复。

**Q: 可以同时使用多个集合吗？**

A: 可以。将 `ROLE_COLLECTIONS` 设为 `"*"` 即可搜索所有集合，或设为列表 `["col_a", "col_b"]` 限定范围。

**Q: 删除集合后能恢复吗？**

A: 不能。删除操作会物理删除 Qdrant 中的向量数据。建议删除前确认内容已备份。
