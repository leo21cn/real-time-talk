## 1. 产品概述

### 1.1 产品名称

**RealTimeTalk** —— 实时对话 AI 助手。

### 1.2 产品定义

RealTimeTalk 是一款 **Web 应用**，以卡通形象（speaker-short-hair-teacher-girl）为载体，用户通过浏览器与形象进行文字对话。形象以**语音+动画视频+对话气泡**三种形式同步输出回复内容。对于较长的回复，系统采用**流式分段生成与播放**机制，确保用户体验流畅，段落间以"思考中"动画无缝衔接。

### 1.3 产品定位

- 一个**带着卡通形象的大模型 Agent**，而非固定逻辑的脚本程序。
- 客户端通过配置文件连接 OpenAI 兼容接口的大模型。
- 动画视频生成逻辑复用现有 `ppt-to-video-vertical` 技能中的语义切片系统。

### 1.4 目标平台

- **运行形态**：Web 应用，通过浏览器访问
- **服务端**：Python FastAPI + Redis + MinIO（Docker Compose 部署）
- **客户端**：现代浏览器（Chrome / Firefox / Edge）

## 2. 功能需求

### 2.1 形象页面常驻

#### 2.1.1 页面属性

| 属性 | 要求 |
|------|------|
| 形象视频 | WebM VP9 Alpha 透明通道视频，叠加于页面背景之上 |
| 背景 | 纯色页面背景 `#FFFFFF`，形象 Alpha 通道自然融合 |
| 默认大小 | 形象视频在页面中居中大比例展示，自适应视口 |
| 点击区域 | 形象显示区域内任意位置均可点击 |

#### 2.1.2 待机状态

- 用户未发起对话时，卡通形象展示**待机循环动画**。
- 待机动画为**独立的轻量呼吸动画**（含眨眼等细微动作），与说话时的语义切片动画在视觉上有明显区分，体量更轻、动作幅度更小。
- 待机动画使用 **HappyHorse API** 从形象源图（`speaker-short-hair-teacher-girl.png`）生成，动作提示词为「轻微呼吸 + 眨眼循环」，时长 5 秒。
- 待机动画循环播放，直到用户点击形象触发交互。
- **循环平滑性约束**：所有循环播放的视频（含待机动画、analysis 思考动画、语义切片）必须满足：**首帧与尾帧画面完全一致**，确保循环衔接无跳变、无闪烁。

#### 2.1.3 交互触发

- **点击形象任意区域** → 弹出文字输入框。形象显示区域内所有位置均可点击触发。
- 输入框弹出后，用户可输入文字内容。
- **确认发送**（键盘回车或点击发送按钮）后，输入框消失，形象进入"思考中"状态。

### 2.2 对话交互流程

```
[待机动画] → 用户点击 → [输入框弹出] → 用户输入+确认 → [输入框消失]
→ [思考中动画] → [回复播放: 视频+语音+气泡] → [回到待机动画]
```

#### 2.2.1 思考中状态

- 形象播放 **analysis 语义切片动画**（食指靠近下巴的思考姿态，来源于 ppt-to-video-vertical 技能切片库）。
- 该动画携带"thinking"标签，作为"思考中"的标准视觉反馈。
- **触发时机**：用户回车发送后，前端**立即**播放 analysis 循环动画，不等待服务端确认，确保反馈零延迟。

#### 2.2.2 回复播放状态

形象回复时，以下三种输出**同时进行**：

1. **动画视频**：形象根据回复文字语义，播放对应的语义切片拼接视频。
2. **语音**：视频携带 TTS 合成的同步音频。
3. **对话气泡**：回复文字以气泡形式从形象上方弹出显示。

**首段切换方式**：收到首段就绪事件后，前端等待当前 analysis 循环播放完毕（不在半帧处打断），然后切换到首段视频开始播放。

#### 2.2.3 气泡行为

- **显示位置**：从形象上方弹出。
- **视觉样式**：**半透明毛玻璃效果**（磨砂玻璃质感），具体参数：
  - 背景：`rgba(255, 255, 255, 0.85)` 半透明白色
  - 圆角：12px
  - 阴影：`0 4px 16px rgba(0, 0, 0, 0.12)` 柔和大阴影
- **字号**：16px。
- **显示方式**：**逐字打字机效果**——气泡文字随语音播放逐字出现，营造"正在说"的实时感。
- **显示时机**：与视频动画及语音播放同步开始。
- **消失时机**：形象说完该段话后，延迟 **2 秒**再开始淡出（fade-out 持续 0.5 秒）。
- **内容**：与当前播放片段的语音文字严格一致。

#### 2.2.4 回复完毕

- 所有回复分段播放完毕后，形象自动**切换回待机循环动画**，等待下一次交互。

#### 2.2.5 用户中断

- 用户在形象处于**思考中**或**说话中**状态时，点击形象即可中断：
  - 立即中断当前回复流程。
  - 清空正在生成但尚未播放的片段。
  - 当前正在播放的视频停止，气泡消失。
  - 形象回到**待机状态**，弹出新输入框供用户重新输入。
- 已在播放的段落无法撤回，但后续内容全部取消。

### 2.3 流式分段生成与播放

#### 2.3.1 触发条件

- 大模型生成的回复文字**超过 50 个字符**时，触发流式分段生成与播放机制（多段并行生成 + 确认式逐段播放）。
- **≤ 50 字符的短回复**：不触发多段并行，但仍走完整流程（TTS → 语义分析 → 视频拼接 → 播放），作为单个片段处理。

#### 2.3.2 分段策略

1. 大模型生成完整回复文本后，**由服务端 StreamingPipeline** 按语义自然段落或句子边界（以中文标点 `。！？；` 为分割点）将文本切分为多个片段。
2. 每个片段独立生成：**TTS 语音合成 → 语义分析 → 切片拼接 → 动画视频**。
3. 第一段生成完毕后立即开始播放，后续段落在后台**并行生成**。
4. 分段权责明确：**LLM 仅负责生成回复文本内容**，服务端的 StreamingPipeline 负责切分与流水线编排。

#### 2.3.3 段落衔接

- 前一段视频播放完毕，但下一段视频尚未生成完毕时：
  - 形象**循环播放 analysis 切片动画**作为过渡。
  - 一旦下一段视频生成完成，**立即无缝切换**到下一段播放。
- 最终一段播放完毕后，形象回到待机动画。

#### 2.3.4 字幕

- 回复视频中**不需要**烧录内置字幕（ASS 字幕）。
- 回复文字仅通过**对话气泡**展示。

### 2.4 多轮对话

- 支持**连续多轮对话**，客户端维护对话上下文历史。
- 每次用户输入时，历史对话记录随请求一同发送给大模型。
- 对话上下文在会话期间持续保留。
- **Token 溢出处理**：当对话历史接近大模型的 token 上限时，采用**智能摘要策略**——调用 LLM 将早期对话压缩为摘要文本，保留摘要 + 近期完整对话，确保上下文不丢失。

### 2.5 多会话隔离

- 不同浏览器标签页/窗口之间通过 **Session Token** 实现完全隔离。
- 每个 Session 拥有独立的：
  - 对话历史上下文
  - 视频生成任务与临时文件
  - WebSocket 连接
- 一个 Session 的对话内容、生成进度、播放状态不影响任何其他 Session。
- Session Token 存储在浏览器 `sessionStorage` 中，关闭标签页即清除。

### 2.6 WebSocket 断线重连

- 网络波动导致 WebSocket 断开后，前端自动重连，恢复同一会话。
- 重连间隔采用递增退避策略（1s → 2s → 4s → 8s，最大 30s）。
- 如重连期间原对话回复中断，前端重新进入待机状态。

### 2.7 异常处理

| 异常场景 | 处理行为 |
|----------|----------|
| 大模型调用失败（网络/API 错误） | 形象上方弹出错误提示气泡（如"抱歉，出了点问题，请稍后重试"），形象回到待机状态 |
| TTS 语音合成失败 | 同上，弹出错误气泡提示 |
| 视频生成失败 | 同上，弹出错误气泡提示 |
| 分段生成中某一段失败 | 已生成的段落正常播放完毕，失败段落以气泡提示，之后回到待机状态 |

### 2.8 输入校验

| 场景 | 校验策略 |
|------|----------|
| 空消息 | 前端拦截，不允许发送 |
| 超长输入 (> 2000 字) | 前端截断至前 2000 字后发送 |
| 特殊字符 | 不拦截，作为普通文本透传给 LLM 处理 |

## 3. 卡通形象与视频系统

### 3.1 形象规格

- **形象标识**：`speaker-short-hair-teacher-girl`（年轻短发干练女教师）
- **绑定音色**：Cherry（芊悦·阳光亲切女声），通过 DashScope TTS API 合成
- **形象来源**：复用 `D:\szp\work\ppt-video\.qoder\skills\ppt-to-video-vertical` 技能中的形象资源与切片库

### 3.2 语义切片系统

系统根据回复文字的语义，通过大模型分析其语义结构，映射到对应的演讲手势切片，再拼接为完整的形象动画视频。

#### 3.2.1 切片标签对照表

| 标签 | 中文含义 | 典型触发语义 |
|------|---------|-------------|
| `greeting` | 问候开场 | 你好、欢迎、嗨 |
| `introduction` | 引入主题 | 今天聊一聊、关于这个问题 |
| `explaining` | 解释说明 | 这个概念、意思是、指的是 |
| `listing` | 列举分点 | 第一、首先、其次、另外 |
| `emphasis` | 强调重点 | 关键、重要、必须、核心 |
| `example` | 举例说明 | 例如、比如、举个例子 |
| `analysis` | 深度分析 / 思考中 | 分析、原因、本质、深层 |
| `comparison` | 对比分析 | 对比、相比、差异、优劣 |
| `transition` | 过渡转换 | 接下来、下面、另外还有 |
| `conclusion` | 总结收尾 | 总结、综上、回顾 |
| `thanks` | 致谢结束 | 谢谢、感谢、欢迎交流 |

#### 3.2.2 切片属性

- 每个切片时长：**5 秒**
- 视频背景：**透明通道（Alpha）**，用于与桌面 UI 背景自然融合
- **循环平滑性约束**：每个切片首帧与尾帧画面完全一致，确保同一标签切片循环播放时无缝衔接
- 拼接过渡：相邻不同切片之间自动插入 0.15 秒 crossfade 过渡
- 过渡规则：遵循 `clips.toml` 中定义的 opening → body → closing 自然过渡序列，LLM 输出的标签序列需经过滤/重排以确保合法过渡
- 拼接方式：运行时使用 FFmpeg stream copy（流拷贝）拼接已预转码的 WebM VP9 Alpha 切片，仅混音时对音频重编码，避免视频重编码开销

#### 3.2.3 语义分析流程

1. 大模型分析当前段落文本的语义结构。
2. 输出语义标签序列（如 `["greeting", "explaining", "emphasis", "conclusion"]`）。
3. 根据标签序列从切片库中选择对应视频片段。
4. 按 TTS 音频时长对切片进行时长对齐（伸缩/裁剪）。

### 3.3 TTS 语音合成

- **合成引擎**：DashScope TTS API
- **默认音色**：Cherry（与 speaker-short-hair-teacher-girl 绑定）
- **语速**：默认 1.0 倍速
- **长文本处理**：超过约 450 字的文本按句子边界自动拆分后分段合成，再拼接

### 3.4 "思考中"动画（analysis 切片）

- 复用语义切片库中的 **analysis** 切片。
- 该切片表现为食指靠近下巴的思考姿态。
- 在以下场景中播放：
  - 用户确认输入后、大模型开始生成回复前（首次"思考中"）。
  - 流式分段播放时，当前段落播完但下一段落尚未生成完毕时（衔接"思考中"），**循环播放**直到下一段落就绪。

## 4. 大模型配置

### 4.1 接口协议

- 服务端通过 **OpenAI 兼容 API** 协议连接大模型。
- 支持标准 Chat Completions 接口（`/v1/chat/completions`）。
- 回复长度通过 `max_tokens` 控制（默认 2048 tokens ≈ 约 1500 中文字），间接限制单次回复的最大分段数。

### 4.2 配置文件

- **格式**：JSON
- **位置**：服务端根目录下，文件名为 `config.json`
- **配置项**：

```json
{
  "llm": {
    "endpoint": "https://api.example.com/v1",
    "api_key": "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "model": "gpt-4o",
    "max_tokens": 2048
  },
  "tts": {
    "api_key": "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "voice": "Cherry",
    "speed": 1.0
  },
  "avatar": {
    "speaker": "short-hair-teacher-girl",
    "clips_dir": "clips/short-hair-teacher-girl",
    "idle_animation": "clips/short-hair-teacher-girl/idle/idle_breathing.webm"
  },
  "system_prompt": "你是一个名叫普兰的知识助手...",
  "redis": {
    "url": "redis://localhost:6379/0",
    "session_ttl_hours": 24
  },
  "minio": {
    "endpoint": "localhost:9000",
    "access_key": "minioadmin",
    "secret_key": "minioadmin",
    "bucket": "realtimetalk"
  },
  "server": {
    "host": "0.0.0.0",
    "port": 8000
  }
}
```

| 字段 | 说明 | 必填 |
|------|------|------|
| `llm.endpoint` | LLM API 基础 URL | 是 |
| `llm.api_key` | LLM API 密钥 | 是 |
| `llm.model` | 模型名称 | 是 |
| `llm.max_tokens` | 单次回复最大 token 数 | 否（默认 2048） |
| `tts.api_key` | DashScope TTS API 密钥 | 是 |
| `tts.voice` | TTS 音色 | 否（默认 Cherry） |
| `tts.speed` | 语速倍率 | 否（默认 1.0） |
| `avatar.speaker` | 形象标识 | 否（默认 short-hair-teacher-girl） |
| `avatar.clips_dir` | 切片资源目录 | 否 |
| `system_prompt` | 角色人设提示词（**优先于**出厂默认文件 `default_system_prompt.txt`） | 否 |
| `redis.url` | Redis 连接地址 | 否（默认 redis://localhost:6379/0） |
| `minio.endpoint` | MinIO 服务地址 | 否（默认 localhost:9000） |

### 4.3 敏感信息保护

- `llm.api_key`、`tts.api_key` 等敏感字段支持通过环境变量覆盖（`LLM_API_KEY`、`DASHSCOPE_API_KEY` 等），避免明文写入配置文件。

### 4.4 对话上下文

- 每次请求携带完整对话历史（system prompt + 历史 user/assistant 消息对）。
- system prompt 定义形象的角色人设（如友好、知识性、自然的口语风格）。

## 5. 非功能需求

### 5.1 性能要求

| 指标 | 要求 |
|------|------|
| 首字延迟（思考中→开始播放） | 流式首段生成尽量快（建议目标 < 5 秒） |
| 分段衔接 | analysis 循环衔接无黑屏或画面断裂 |
| 语音与视频同步 | 口型/手势动画与对应语音片段无显著错位 |

### 5.2 可用性要求

- 页面布局简洁，形象居中，输入交互直观（单行输入 + 回车发送）。
- 气泡文字清晰可读，字号适中。
- 启动方式简单：`docker compose up` 后浏览器访问。

### 5.3 可靠性要求

- 网络异常时给出明确反馈（错误气泡），不卡死或崩溃。
- 连续多轮对话中，单次异常不影响整体会话。

### 5.4 可维护性要求

- 配置文件独立于程序，方便用户修改。
- 切片库路径可配置，便于切换形象或更新切片资源。

## 6. 约束与假设

### 6.1 技术约束

- 依赖浏览器环境（Chrome / Firefox / Edge 最新版本）。
- 服务端依赖：Docker + Docker Compose。
- 依赖外部 API：大模型 API（OpenAI 兼容）、DashScope TTS API。
- 切片库资源预先存在于本地，不在首次运行时动态生成。

### 6.2 外部依赖

| 依赖项 | 用途 |
|--------|------|
| OpenAI 兼容大模型 API | 对话生成 + 语义分析 |
| DashScope TTS API | 语音合成（Cherry 音色） |
| FFmpeg | 视频切片拼接与合成 |
| Redis | 会话状态存储、对话历史持久化 |
| Nginx | React 前端静态文件 serve + API/WebSocket 反向代理 |

### 6.3 假设

- 用户具备基本的大模型 API 访问能力（拥有 API Key）。
- 切片库资源（`clips/short-hair-teacher-girl/` 目录下的 .mkv 文件）已从 ppt-video-vertical 技能复制就绪。首次启动前通过 `convert_clips.py` 将 .mkv 转码为 .webm（VP9 Alpha），运行时 FFmpeg 通过 stream copy 拼接，不重编码。
- 待机动画 `idle_breathing.webm` 已通过 HappyHorse API 预生成，存放在 `clips/short-hair-teacher-girl/idle/` 中。
- 语义切片首尾帧一致性作为预置条件接受（HappyHorse prompt 已含「动作结束时回到起始姿态」）。

## 7. 术语表

| 术语 | 定义 |
|------|------|
| **卡通形象** | speaker-short-hair-teacher-girl，Web 页面中的 AI 对话角色 |
| **语义切片** | 根据文字语义从切片库中选择的 5 秒手势动画片段 |
| **流式分段** | 长文本回复按语义拆分为多个段落，逐段生成视频并播放 |
| **分析动画 / analysis** | 食指靠近下巴的思考姿态切片，用于"思考中"和段落衔接 |
| **对话气泡** | 形象上方弹出的文字展示 UI 元素 |
| **待机动画** | 用户未交互时形象展示的循环小动画 |
